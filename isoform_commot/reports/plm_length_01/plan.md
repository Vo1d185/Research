# 实验一:V12 在长、短蛋白配对上的区分能力

**状态:预注册计划。** 2026-11-19 起草;本文件提交后才运行正式实验,`run_length.sh` 会检查本文件已提交且工作区无改动。
提交前不对本实验的数据打分。

## 0. 问题

- **E1(观察):** 在大量、没有参与 V12 训练的人类 PPI 数据上,长配对的 AUROC 是否低于短配对?
- **E2(干预):** 同一批短配对,只把序列加长、不改动原有序列,AUROC 是否下降?
  E2 用来区分两种解释:是"长度本身"让 V12 变差,还是"长蛋白的配对本来就难"。

**背景:已有证据不一致,而且都不是受控比较。**
- 小鼠 LR 面板(`stage2_ppi_01`,探索性):≤ 1603 token 时 AUROC 0.813,> 1603 token 时 0.645。
- 人类 LR 基准 H-A(`plm_lr_benchmark` 第 11.2 节):两个蛋白都 ≤ 800 aa 时 0.828,至少一个 > 800 aa 时 0.762。
  这两组的类别构成和训练集重叠情况都不同。截断到 1603 token 与不截断几乎没有差别(0.765 对 0.762)。

## 1. 数据

- **主数据集:** Bernett 等 2024 年的人类 PPI 金标准测试集(*Briefings in Bioinformatics* 25: bbae076;
  HF `danliu1226/Bernett_benchmarking`,`pairs_uniprot_seqs_test.csv`,sha256 前 16 位 `89f164f9bd391fd3`)。
  - 规模:52,048 对,正负样本各 26,024;3,022 个蛋白,长度 51–5,183 aa。
  - 负样本与正样本的长度分布接近(token 数中位数 917 对 923),因此同一长度组内的正负样本可以直接比较。
- **剔除 V12 训练集中出现过的配对:** 训练集为 HF `danliu1226/STRING_V12_TrainingSet@819f938`,共 666,903 对。
  按两条序列完全一致匹配无序配对,训练中的正样本和负样本都算。
  - 剔除 2,203 对,其中 25 对在训练集中是正样本、在本测试集中是负样本。
  - 剩下 **49,845 对(正 23,984、负 25,861)作为主分析集。**
- **训练重叠分层:** 两个蛋白都在训练集中出现过;只出现过一个;都没出现过。
- **LR 复制分析(描述性,不新打分):** 用 `plm_lr_benchmark` 中 H-A 已有的 V12 分数
  (CellChatDB v2 人类单基因、非同源配对,1,127 个正样本),按同样的 token 规则重新分组。

## 2. 长度

- **定义:** L = len(A) + len(B) + 3,即模型实际读入的 token 数。
- **主对比:** 短配对 L ≤ 1603,长配对 L > 1603。1603 是官方训练脚本的 `max_length`。
- **描述性分段**(主分析集的正 / 负样本数):

  | 分段 | 正样本 | 负样本 |
  |---|---|---|
  | ≤ 600 | 5,635 | 5,628 |
  | 601–1000 | 7,575 | 8,850 |
  | 1001–1603 | 6,865 | 7,271 |
  | 1604–2400 | 2,567 | 2,766 |
  | > 2400 | 1,342 | 1,346 |

- **单独报告:** 含有超过 1,996 aa 蛋白的配对(正 1,111、负 1,190)。1,996 aa 是 V12 训练集中最长的蛋白,更长的蛋白 V12 从没见过。

## 3. 打分

humanV12(`models/plm_650m_humanV12`,sha256 `92565937…`),用 `plm_score.py` 打分,不截断,取两个输入顺序的平均值。
这与此前所有 V12 打分的做法相同。

## 4. E1:观察

- **指标:** 组内 AUROC,即正负样本都取自同一长度组。AUPR 和正负样本分数的中位数只作描述。
- **Δ_obs = AUROC_短 − AUROC_长。** 95% 区间用 bootstrap:2,000 次,`numpy.random.default_rng(1)`,在每个长度组、每个标签内分别有放回抽样。
- **稳健性(预先登记):**
  1. 在三个训练重叠层内分别计算 Δ_obs;
  2. 按蛋白随机分成两半,重复 20 次(种子 1–20)。每一半只用两个蛋白都在这一半的配对,计算 Δ_obs,报告 40 个值中与总体同号的比例;
  3. 描述性分段曲线。
- **判定:**

  | 条件 | 结论 |
  |---|---|
  | Δ_obs ≥ 0.05,区间下限 > 0,且三个重叠层的 Δ 同号 | 长配对明显更差 |
  | 区间下限 > 0,但不满足上一行 | 长配对略差 |
  | 区间完全落在 [−0.05, 0.05] 内,且不满足以上两行 | 没有实质差异 |
  | 其他 | 不确定 |

## 5. E2:干预(加长序列)

- **样本:** 从主分析集 L ≤ 1000 的配对中,按训练重叠层分层随机抽取 2,000 个正样本和 2,000 个负样本(种子 1)。
- **加长方式:** 在两条序列的 C 端各补上一半长度,使 L 分别达到 T = 1603、2400、3200。补的长度为奇数时,多出的 1 个补给 B。
  原有序列一个残基都不改。
- **补上什么(两种,都做):**
  1. **自身打乱:** 从这个蛋白自己的序列中有放回地抽取残基,保持氨基酸组成,但不带结构信息;
  2. **外源天然序列:** 随机选一个与 A、B 都没有互作记录的蛋白(在 Bernett 测试集全部正样本中查),
     取它的连续片段;一个蛋白不够长时,接着取下一个。种子固定。
- **Δ_pad(T) = AUROC_原始 − AUROC_加长(T)**,在同一批配对上计算,对配对做 bootstrap(2,000 次,种子 1)。
- **判定(以 T = 2400 为准,两种补法都要满足):**

  | 条件 | 结论 |
  |---|---|
  | Δ_pad ≥ 0.05,且区间下限 > 0 | 长度本身降低区分能力 |
  | 区间完全落在 [−0.05, 0.05] 内 | 长度本身影响不大 |
  | 其他 | 不确定 |

  另外报告正样本分数中位数随 T 的变化。

## 6. 结论与后续

| E1 | E2 | 结论 | 对后续的含义 |
|---|---|---|---|
| 明显更差或略差 | 长度本身降低 | V12 的长序列问题来自模型对长度的处理 | 胞外段打分或裁剪有望提高质量,值得做 |
| 明显更差或略差 | 影响不大 | 长配对本身更难(序列内容或标签),不是长度造成的 | 裁剪不一定有用 |
| 没有实质差异 | — | 长度不是 V12 的主要问题 | 小鼠面板上的长度差异要另找原因,例如类别构成 |
| 其他组合 | — | 如实报告 | — |

## 7. 计算量与执行

- **作业数:** 主分析集 49,845 对 × 2 个输入顺序,约 10 万个作业;E2 为 4,000 对 × 3 个长度 × 2 种补法 × 2 个顺序 = 48,000 个作业,序列较长。
- **用时:** 按此前的速度(LR 基准约 9 个作业/秒,Stage 2 第一步约 5 对/秒),估计 GPU 共需 6–10 小时,环境 `plminteract`。
- **步骤**(在 `isoform_commot/` 目录下):
  1. 提交本文件和代码,记下提交号。
  2. 下载测试集(只做一次;`commot-research`;按固定 revision 下载并核对 sha256):
     `python plm_length.py fetch --output data/lr_benchmark/plm_training/Bernett_benchmarking/pairs_uniprot_seqs_test.csv`
  3. 冒烟(200 对,E2 每类 10 对;结果不解读):
     `bash reports/plm_length_01/run_length.sh --smoke --runs analysis_length_smoke --test-file data/lr_benchmark/plm_training/Bernett_benchmarking/pairs_uniprot_seqs_test.csv --training-root data/lr_benchmark/plm_training --checkpoint models/plm_650m_humanV12/pytorch_model.bin --base-model models/esm2_t33_650M_UR50D --plm-python /home/liu/.conda/envs/plminteract/bin/python --workers 2`
  4. 正式:同样的参数,去掉 `--smoke`,`--runs analysis_length_main`,加 `--results reports/plm_length_01/summary`。
     脚本会检查本文件已提交且没有改动。中断后加 `--resume` 续跑,已打完的块自动跳过。
  5. 提交 `reports/plm_length_01/summary/`。运行目录 `analysis_length_*` 被 `.gitignore` 的 `analysis*/` 规则忽略。
- **本地验证(不是结果):** 在没有 GPU 的机器上,用真实的两个数据文件跑完整的 `prepare`(sha256 核对通过):
  剔除 2,203 对,主分析集 49,845 对(正 23,984、负 25,861),V12 训练集中最长的蛋白 1,996 aa,
  E2 抽到 4,000 对,共 147,690 个作业、74 块。打分换成假打分器后,整条流程能跑通:
  埋入长度效应时判为"长配对明显更差"(Δ = 0.114,区间 [0.107, 0.121])和"长度本身降低区分能力";
  不埋时判为"没有实质差异"(Δ = 0.0003,区间 [−0.0013, 0.002])和"长度本身影响不大"。评价一次约 30 秒。

## 8. 已知局限

1. Bernett 数据是一般 PPI,多数是细胞内的复合物,不是配体-受体。LR 只有复制分析,正样本约 1,100 个。
2. Bernett 的负样本是随机抽取的无互作记录配对,不是实验测得的阴性。
3. 加长用的不是真实结构域。E2 只能说明"多出来的序列会不会干扰判断",不能完全等同于真实的长蛋白。
